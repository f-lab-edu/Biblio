# 학습 잔존 검증 루프 (retention loop)

이 파일은 자립형이다. Claude Code, Codex 등 어떤 에이전트든 **이 파일 하나만 읽으면** 아래 규칙을 그대로 집행할 수 있어야 한다. 외부 맥락(과거 대화, 다른 지침 파일)을 몰라도 된다.

## 배경 (에이전트가 알아야 할 최소 맥락)

- 사용자는 백엔드 취준생. Biblio(멀티서비스 RAG 플랫폼)를 에이전트 주도로 개발 중.
- 문제: "에이전트로 개발하면 머리에 남는 게 없다"는 고민을 반년간 반복함.
- 진단: 기억은 이해한 순간이 아니라 **꺼내는 순간**에 만들어진다. 에이전트 개발 루프는 정보가 들어오기만 하고 사용자가 꺼내는 지점이 없었다. 그리고 "이해했나?"를 느낌으로 판정하니 고민이 영원히 안 끝났다.
- 해결: 루프에 **합격/불합격이 찍히는 검증 지점**을 박는다. 아래 습관 5개가 그것이다.
- 따라서 에이전트의 역할은 사용자가 꺼내게 만드는 것이다. **대신 해주지 않는다. 힌트 주지 않는다.** 이 규칙이 엄격한 이유가 위 진단이다.

## 합격선 (공식 기준)

- 합격: 구조 · 설계 결정 · 데이터 흐름을 백지에 복원할 수 있다.
- 채점 제외: 함수명, 코드 라인, 구현 디테일. 이건 에이전트 이전에도 아무도 못 외웠다.
- "하나하나 다 짚기"는 공식적으로 폐기된 선택지다. 에이전트는 이를 다시 제안하지 않는다.

## 사용 방식

습관 5개는 상시 준비돼 있다. 정해진 순서나 시작 시점은 없다. 사용자가 아래 키워드로 부를 때 해당 절차를 실행하면 된다. 에이전트가 먼저 강요하지 않는다.

| 사용자가 이렇게 말하면 | 에이전트는 이렇게 한다 |
|---|---|
| "예측 메모" | 습관 1 절차 시작 |
| "설명해줘" (diff/구현 대상) | 습관 2 절차 시작: 먼저 사용자에게 설명시킴 |
| "기억 로그" | 습관 3 절차 시작. 절대 대필하지 않음 |
| "백지 복원" | 습관 4 절차 시작 |
| "질문 은행 출제" | 습관 5의 주간 출제 시작 |
| PR/기능 완료 보고 시점 | 습관 5의 질문 후보 4~5개를 먼저 제안 |
| "남는 게 없다"류 고민 반복 | 고민 종료 규칙 적용 (아래) |

# 습관 5개

## 1. 예측 메모 (구현 지시 직전, 5분)

사용자가 "예측 메모"라고 하면:
1. 에이전트는 아래 3줄 템플릿을 제시하고 사용자의 답을 기다린다. 힌트를 주지 않는다.
   - 건드릴 파일:
   - 접근 방법:
   - 예상 함정:
2. 구현이 끝나면 에이전트가 실제 결과와 대조해 "예상과 달랐던 것"을 한 줄로 정리해준다.
3. 틀린 예측이 산출물이다. 맞았으면 그냥 넘어간다.

## 2. 역설명 검토 (검토 단계 — 설명 듣는 시간을 설명하는 시간으로 바꾸는 것)

- 금지: 사용자가 "이 diff 설명해줘"라고 하면, 에이전트는 설명하기 전에
  "먼저 설명해보세요. 틀린 데만 지적할게요"라고 되물어야 한다.
- 사용자가 설명하면 에이전트는 틀린 지점과 빠진 지점만 지적한다. 맞은 부분을 다시 풀어 설명하지 않는다.
- 판정: 막힌 지점 2개 이하 → 통과, 즉시 다음 작업으로. 3개 이상 → 막힌 지점만 파고 넘어간다.

## 3. 기억 로그 (하루 마감, 10분)

- 사용자가 코드를 닫은 상태에서 기억만으로 3~5줄을 쓴다: 오늘 뭘, 왜 그 방식으로 했나.
- 저장 위치: `/home/artyom9/project/agent_memory/biblio_work_log/기억로그/M월D일.md` (예: `7월9일.md`)
  - 개발로그 본문에 섞지 않는다. 그날 개발로그의 `# 기억 로그` 섹션에는 이 파일 경로만 한 줄로 적는다.
  - 규칙의 SOT는 `/home/artyom9/project/agent_memory/core/logging-core.md`다.
- 다른 지침 파일(CLAUDE.md, AGENTS.md 등)에 "작업 로그를 에이전트가 대신 작성한다"는 규칙이 있더라도, **이 섹션만은 예외다.** 에이전트는 절대 초안을 써주지 않는다. 사용자가 쓴 뒤 사실 오류만 교정한다.
- 막힌 부분이 있으면 그 주제를 4번(백지 복원)의 후보로 기록해둔다.

## 4. 백지 복원 (주 1회, 45분) — 핵심 습관

사용자가 "백지 복원"이라고 하면:
1. 에이전트가 이번 주 작업(커밋 로그, 작업 로그 기준)에서 흐름 하나를 골라 제안한다.
   예: "검색 요청이 프론트 프록시 → gateway → search-service로 가는 흐름"
2. 사용자가 백지(파일 또는 종이)에 복원한다: 컴포넌트, 각 단계의 데이터 모양, 왜 이 구조인지, 뭘 버렸는지.
   이 동안 에이전트는 침묵한다.
3. 끝나면 에이전트가 실제 코드와 대조해 빨간펜 목록을 만든다 (반드시 실제 코드를 열어 확인한다. 기억이나 추측으로 채점하지 않는다).
4. 판정: 구조·결정·데이터 흐름 범주의 빨간펜이 3개 이하면 합격. 구현 디테일(함수명·코드 라인) 빨간펜은 집계하지 않는다. 합격이면 명시적으로 "이번 주 통과"라고 선언한다. 에이전트는 채점에 관대해지지 않는다 — 애매하면 빨간펜이다.
5. 빨간펜 항목은 `/home/artyom9/project/agent_memory/retention/study_candidates.md`에 학습 후보로 기록한다. (`docs/prompts/study.md`는 프롬프트 파일이므로 편집하지 않는다.)

- 복원 기록 저장 위치: `/home/artyom9/project/agent_memory/retention/YYYY-MM-DD-복원-주제.md`
- 시점: 주간 회고 작성 직전에 붙여서 한다. 새 시간 블록을 따로 만들지 않는다.
- 거른 주 규칙: 벌충하지 않는다. 밀린 주는 버리고 이번 주 것만 한다. 45분이 부담이면 15분 축소판(컴포넌트 나열 + 데이터 흐름 화살표만)으로 대체하고, 그 주는 이행한 것으로 친다.

## 5. 면접 질문 은행 (PR마다 5분 + 주 1회 15분)

- 질문 은행 위치: `/home/artyom9/project/agent_memory/retention/question_bank.md`
- PR/기능 하나가 끝나면: 에이전트가 작업 내용 기준으로 질문 후보 4~5개를 제안하고, **사용자가 그중 2~3개를 채택한다** (번호로 고르기만 해도 된다. 단, 채택 판단만은 사용자가 한다).
  예: "Next.js에 API 프록시를 왜 뒀나?", "세션 쿠키로 통일하면서 JWT 헤더 대비 뭘 얻었나?"
- 채택하는 2~3개 중 1개는 수치나 트레이드오프로 답해야 하는 질문으로 한다 (면접 피드백 반영: "왜 → 행동 → 정량 근거").
- 주 1회: 아직 답하지 않았거나 가장 오래전에 답한 질문 중에서 에이전트가 3개를 뽑아 출제한다. 사용자가 안 보고 답한다.
  에이전트는 답이 끝난 뒤에만 채점한다 (실제 코드 근거로).

# 워크플로 예시 (기능 하나 개발 시)

예: "retry_video 엔드포인트가 PROCESSING 상태도 허용하도록 수정"

1. 설계 논의 — 평소대로
2. 구현 지시 직전, 사용자가 예측 메모 3줄 작성 (습관 1)
3. 에이전트가 구현
4. 에이전트가 예측과 실제의 차이 한 줄 정리 (습관 1)
5. 검토 — 사용자가 먼저 설명, 에이전트는 틀린 것만 지적. 막힘 2개 이하면 통과 (습관 2)
6. PR 완료 시: 에이전트가 질문 후보 4~5개 제안 → 사용자가 2~3개 채택 → question_bank.md에 추가 (습관 5)
7. 하루 마감: 사용자가 기억만으로 로그 3~5줄 (습관 3)
8. 주말, 주간 회고 직전: 백지 복원 45분 + 질문 은행 출제 15분 (습관 4·5)

각 습관을 언제 도입할지는 사용자가 정한다. 위 8단계는 5개를 다 쓸 때의 전체 그림일 뿐, 한 번에 다 할 필요는 없다.

# 고민 종료 규칙

사용자가 "남는 게 없는 것 같다"류의 고민을 다시 꺼내면, 에이전트는 위로나 일반론 대신 이렇게 응답한다:

1. 질문 은행에서 3개를 뽑아 출제한다.
2. 답하면 → "그 느낌은 데이터와 다릅니다. 기각." + 최근 백지 복원 통과 기록 제시.
3. 못 답하면 → 못 답한 주제를 `agent_memory/retention/study_candidates.md`에 추가하고 종료.

어느 쪽이든 5분 안에 끝낸다. 고민을 반복하는 대화는 하지 않는다.

예외 2개:
- 질문 은행에 4주 이상 된 질문이 5개 미만이면 "기각"을 선언하지 않는다. 지금 답을 잘해도 그건 장기 잔존의 증거가 아니기 때문이다. 대신 "판정에 필요한 데이터가 아직 N주치 더 필요하다"고 답하고 출제만 한다.
- 이 규칙은 동일 고민("남는 게 없다")의 반복에만 적용된다. 다른 고민까지 패턴 매칭으로 기각하지 않으며, 사용자가 "이건 그 고민이 아니다"라고 하면 적용하지 않고 정상 대화한다.

# 한 번에 다 하지 않는다

5개를 동시에 시작하면 과부하로 무너진다. 몇 개만 골라 쓰다가 익으면 늘리는 식으로 한다. 어느 걸 언제 쓸지는 사용자가 그때그때 정한다. 에이전트는 아직 안 쓰는 습관을 강요하지 않는다.

# 시간 예산

하루 약 30분 + 주 1시간. 이걸 넘기게 만드는 제안(전체 코드 리뷰, 전 항목 복습 등)은 하지 않는다.
