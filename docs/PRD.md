# Biblio 프로젝트 PRD

**프로젝트 이름:** Biblio

---

## 1. 요약(Summary)

### 1.1 목적
본 프로젝트는 NotebookLM과 같은 멀티모달 RAG 플랫폼을 End-to-End로 직접 구축하여 핵심 원리를 깊이 있게 학습하고, 텍스트 검색을 통해 긴 영상 시청의 비효율을 해소하여 필요한 맥락을 즉시 찾아내는 서비스를 제작하는걸 목적으로 한다.

### 1.2 성공기준

1. **목표:** 데이터 수집, 가공, 적재, 서빙에 이르는 전체 데이터 사이클을 자동화된 파이프라인으로 구현
   - **성공기준:** 사용자가 영상을 업로드한 시점부터 검색 가능한 상태가 될 때까지의 전 과정이 사용자의 개입 없이 유기적으로 연동되어야 한다.

2. **목표:** 업로드한 영상에 대한 검색과, 응답 내용의 영상속 지점을 정확히 제공
   - **성공기준:** 최종 사용자 인터페이스(UI)에서 시맨틱 검색에 대한 응답을 출력하고, 타임스탬프 클릭 시 해당 지점부터 영상 재생이 가능해야 하며 응답 내용과 재생 시점이 오차 없이 일치되어야 한다.

3. **목표:** 예외 상황을 고려한 견고한 시스템 설계 및 운영
   - **성공기준:** 트래픽 폭주나 시스템 장애 상황에서도 서비스 가용성을 유지하고, 데이터 무결성을 보장

## 2. 고객 및 사용자 요구 (Customer & User Needs)

### 1. 서비스 사용자
긴 강의 영상, 회의 녹화본, 뉴스 클립 등에서 특정 정보를 빠르게 찾고 싶은 학습자

* **주요 작업과 제약 사항:**
    * 원하는 내용을 찾는 과정에서 타임라인을 무작위로 클릭하거나 배속으로 돌려보는 과정에서 시간소요가 많이 됨
    * 텍스트 문서(PDF, 블로그)와 달리 영상은 Ctrl+F가 불가능하여, 찾고자 하는 내용이 있는 위치를 다시 찾기 어려움.

### 2. 서비스 관리자
ai engineer, mlops 와 같이 서비스 운영 및 품질 관리를 담당하는 엔지니어

* **주요 작업:**
    * 데이터 파이프라인 상태를 모니터링하고 오류 발생시 해당 지점을 수정, 필요에 따라 데이터를 재처리 하거나 삭제
    * 품질 개선을 위해 사용자 피드백을 수집 하고, AI 모델을 개선 및 재배포

## 3. 제품 범위 및 사용 사례(Product Scope & Use Cases)

### 3.1 사용자 관련 주요 기능

> * **must:** 필수 사항
> * **should:** 중요하지만 필수는 아님
> * **could:** 추가적인 편의사항

#### Must Have

1. **영상 업로드 및 저장:** 사용자가 컴퓨터의 로컬 영상 파일을 직접 업로드하거나, 유튜브 등 외부 플랫폼의 영상 URL을 입력하여 클라우드 스토리지에 저장한다.

2. **영상 처리:** 영상의 음성과 구간별 핵심 장면(Keyframe)을 분석하여 멀티모달 임베딩을 생성한다. 이를 통해 대사로 언급되지 않은 슬라이드 내용이나 영상의 전반적인 맥락까지 포괄하는 검색을 지원한다.

3. **검색 및 타임스탬프 제공:** 사용자가 자연어 질문이나 특정 용어를 입력하면, 텍스트의 의미(Context)와 단어 일치(Keyword)를 복합적으로 분석하여 답변을 생성한다. 그리고 답변의 근거가 되는 영상 속 핵심 구간을 찾아 클릭 가능한 타임스탬프로 제공하며, 클릭 시 해당 시점부터 영상이 재생된다.

4. **카테고리 지정:** 사용자가 영상 파일/URL 업로드 시, 영상의 도메인(예: 일반, IT, 의학, 법률)을 필수로 선택하게 하여 추후 학습 데이터를 위한 메타데이터를 확보한다.

#### Should Have

1. **작업 재시도:** 업로드 이후, 영상 처리가 제대로 이루어지지 않은 경우 사용자가 재시도를 누르면 기존 데이터를 삭제하고 처리과정을 처음부터 다시 시작한다.

2. **처리상태 조회:** 사용자가 업로드한 영상의 현재 상태(업로드 완료, 영상 처리중, 완료)를 실시간으로 조회할 수 있어야 한다.

3. **사용자 영상 목록 관리:** 사용자가 본인이 업로드한 영상들을 목록으로 보고, 개별 영상을 삭제하거나 제목을 수정할 수 있다.

4. **사용자 피드백:** 응답에 대해 만족여부에 따라 좋아요/싫어요 버튼을 눌러 서비스 개선에 반영한다.

#### Could Have

1. **영상 카테고리(도메인) 기반 응답:** 사용자는 영상 업로드시 카테고리(ex: 일반, 법률)를 선택하여 특정 도메인에 대한 최적화된 검색 결과를 얻을 수 있다.

### 3.2 관리자 관련 주요 기능

#### Must Have

1. **파이프라인 단계별 상태 모니터링:** 업로드 부터 영상 처리, db저장 각 단계의 성공/실패 여부와 상태, 소요시간을 로그 또는 대시보드 형태로 확인할 수 있어야 한다.

2. **AI 모델 설정 및 재 임베딩:** STT 및 임베딩 모델의 버전을 관리하고 교체할 수 있어야 한다. 모델 변경 시 기존 멀티모달 청크를 새로운 모델로 다시 벡터화하여 DB를 갱신(Re-indexing)하는 작업을 실행할 수 있어야 한다.

3. **오류 데이터 강제 삭제:** 처리 과정에서 오류가 발생하여 멈추거나 잘못 처리된 데이터를 관리자가 수동으로 DB 및 스토리지에서 영구 삭제할 수 있어야 한다.

#### Should Have

1. **실패 작업 선별적 재처리:** 일시적인 오류로 실패한 작업에 대해, 전체 파이프라인을 다시 돌릴 필요 없이 실패한 단계부터 작업을 다시 시작 할 수 있어야 한다.

2. **피드백 기반 데이터셋 구축:** 사용자의 명시적 피드백(좋아요/싫어요)과 묵시적 피드백을 수집한다. 관리자가 이 데이터를 검수하여 학습용 데이터셋으로 확정하고 저장할 수 있어야 한다.

3. **모델 재학습 및 평가 파이프라인:** 구축된 데이터셋을 활용해 주기적 또는 관리자 요청 시 모델을 재학습 시키는 워크플로우를 지원해야 한다. 학습된 모델은 기존 모델과 성능(정확도, 재현율 등)을 자동 평가하여, 성능이 향상된 경우에만 배포 가능한 상태로 전환한다.

#### Could Have

1. **도메인 특화 임베딩 모델 파인튜닝:** 사전학습된 범용 임베딩 모델로 검색 품질이 충분하지 않은 특수 도메인(의료, 법률 등)에 대해, 관리자가 도메인 특화 학습 데이터셋을 업로드하여 임베딩 모델을 파인튜닝할 수 있다. 또한 모델 재학습 및 평가 파이프라인 을 통해 배포 가능해야 한다.

## 4. 비기능적 요구 사항(Non-Functional Requirements)

### 4.1 성능 및 응답성

1. **검색 응답 속도:** 사용자의 텍스트 질의(Query)에 대한 시맨틱 검색 결과는 5초 이내에 반환되어야 한다.

2. **영상 처리 파이프라인 처리량:** 업로드된 1시간 분량의 FHD(1080p) 영상 기준으로, STT 및 벡터화(Embedding) 과정을 포함하여 업로드 완료 후 10분 이내 에 검색 가능한 상태가 되어야 한다.

3. **동시성 처리:** 단일 인스턴스 기준, 최소 100명 이상의 사용자가 동시에 1GB 이상의 영상을 업로드하더라도 시스템이 중단되지 않아야 하며, 업로드 세션이 유지되어야 한다.

### 4.2 가용성 및 신뢰성

1. **서비스 가용성:** 시스템은 99%의 가용성을 목표로 하며, 트래픽 폭주 시에도 최소한 '검색' 기능은 유지되어야 한다. (업로드는 대기열로 지연 처리 가능)

2. **데이터 무결성 및 내구성:**
   - 업로드된 영상 원본과 추출된 메타데이터(스크립트, 임베딩 벡터)는 유실되지 않아야 하며, 내구성 높은 스토리지와 DB에 저장되어야 한다.
   - 또한 모든 재처리 과정은 트랜잭션으로 관리되어야 하며, 실패 시 유령 데이터(Orphaned Data)가 남지 않도록 완전한 롤백 또는 삭제가 보장되어야 한다

3. **장애 격리:** 특정 영상의 분석 작업이 실패하더라도, 다른 사용자의 영상 처리나 전체 검색 서비스에 영향을 주지 않아야 한다.

4. **검색 신뢰성:** 검색 실패율(Zero Result Rate) 5% 미만 을 유지해야한다.

### 4.3 확장성

1. **처리량 유연성:** 대기 중인 영상 처리 작업이 임계치를 초과할 경우, 워커(Worker) 노드에 대한 수평 확장(Scale-out)이 가능해야 한다.

2. **검색 성능 최적화:** 영상 데이터 및 벡터 데이터베이스(Vector DB)의 용량이 증가하더라도 검색 속도가 데이터 양에 비례해 선형적으로 느려지지 않도록 보장해야 한다

### 4.4 모니터링 및 유지보수성

1. **실시간 모니터링:** 각 파이프라인 단계의 실제 상태와 대시보드에서의 정보 간의 지연시간은 5초 미만이여야 한다.

2. **모델 버전 관리:** STT 및 Embedding 모델 변경 시, 서비스 중단 없이 교체가 가능해야 한다. 모델 교체 후 문제가 발생할 경우 이전 버전으로 즉시 롤백할 수 있어야 한다.

### 4.5 보안

1. **데이터 접근 제어:** 사용자는 본인이 업로드한 영상과 그에 대한 검색 결과에만 접근할 수 있어야 한다.
