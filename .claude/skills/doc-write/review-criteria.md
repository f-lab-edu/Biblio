# 문서 피드백 기준

> 이 기준은 문서 피드백 전 반드시 읽고 숙지해야 한다. 임의로 피드백되는 상황이 존재해선 안 된다.

---

## 피드백 기준 (번호는 우선순위와 무관)

### 1. SOT 모순 검증 (최우선)

- `docs/system-design.md`를 기준으로 설계 사항에 모순이 발생하지 않았는지 검증한다
- 상태 전이, 컴포넌트 책임 범위, 데이터 흐름, API 계약 등이 system-design과 일치해야 한다

### 2. 컴포넌트 간 충돌 확인

- `docs/Tech_Spec/` 내 이미 작성된 다른 컴포넌트 Spec/Plan 문서와 충돌하는 사항이 없는지 확인한다
- 확인 대상: 로직, 변수명, 기술스택, 에러 코드, 메시지 스키마, 상태값 등

### 3. 임의 작성 내용 검출

- 사전에 합의되지 않았거나 system-design 문서에 없는 임의로 작성된 내용이 존재하는지 확인한다
- 근거 없이 추가된 기술 선택, 정책, 수치 등을 지적한다

### 4. 완료 기준 충족 여부

문서 작성 지침에 명시된 **Tech Spec 작성 완료 기준**을 충족하여 팀원 또는 AI Agent에 즉시 작업 할당이 가능한 수준인지 확인한다:

- (1) 충분한 맥락
- (2) 구조 (디자인)
- (3) 요구사항 (제약사항 포함)
- (4) 검증(완료) 기준
- (5) 결과물: SPEC.md, PLAN.md

### 5. 문장 품질

- verbose하거나 중복되는 요소가 없는지 확인한다
- 간결하고 명확한 표현을 권장한다

### 6. 오버엔지니어링 검출

- MVP 수준의 서비스 구현을 초과하는 오버엔지니어링된 사항이 없는지 확인한다
- 과도한 추상화, 불필요한 인프라 구성, MVP에 불필요한 기능 등을 지적한다

---

## 피드백 출력 형식

각 피드백 항목은 **구체적인 수정 지시** 형태로 작성한다:

```
[기준 N] 섹션 X.X: 현재 "A"로 작성되어 있으나, system-design 기준 "B"로 수정 필요
```

모든 기준을 통과한 경우 **PASS**를 명시한다.
